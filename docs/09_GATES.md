# 09 — Internal gates

Gate protocol: six lenses state their strongest REMAINING objection (no compliments), red
team gives the 3 strongest arguments against the output + a kill-list. The program responds:
**ADOPTED** (docs changed), **PARTIAL** (changed within founder defaults), or **LOGGED**
(contradicts a founder-decided default D1–D13 — founder reviews asynchronously; build
continues per contract). Objections are condensed faithfully; they were generated by an
independent review panel against the docs as committed at each gate.

---

# GATE 1 — after Stage A (2026-08-25)

## Lens objections

### Audit partner — the L2 claim and the hours claim cannot both be true as written
"Radically cut hours" + "everything L2-validated" is unresolved: if validation means
re-performing the comparison against source, the hours come back (DataSnipper-plus); if it
means signing an auto-drafted workpaper, the evidence was obtained by a pipeline whose
reliability the firm never established — and synthetic-dataset results are worthless as an
ISA 500/AS 1105 evaluation of the tool. Typed exceptions invert skepticism: attention flows
to flags while the dangerous population is the machine-passed 95% (silent false negatives —
a mis-extracted date producing a clean tie that never happened). Provenance documents that
a link exists, not that it is true. Sign-off attributes machine work to a human preparer.
*Concrete failure*: inspection pulls a machine-passed item whose "approval" was a misfiled
document; no deviation, no human look, no record of what L2 examined; insufficient-evidence
finding + failure-to-evaluate-the-tool finding.
**Demanded**: an explicit L2 evidence contract (validation act defined per item; honest
attribution "performed by OTTO run #x, validated by X"); an on-engagement tool-reliability
control (blind re-performance of a random subsample of machine-PASSED items, measured
false-negative rate); honest hours math.
**Response: ADOPTED.** ADR-012 (L2 evidence contract: per-rung policy, side-by-side
validation act, confidence = triage only, never bypass), verification-spot-check control on
machine-passed items added to the data model (`verification_check`) and S7/S8 flows,
workpaper attribution changed to "Performed by OTTO engine run … / Validated by …".
Synthetic-dataset results demoted to build-time regression (ASSUMPTIONS A9 reworded; PRD
acceptance reworded). Hours model: logged as pre-pilot benchmark (A11) — cannot be honestly
computed from synthetic data.

### Senior manager — the export boundary is on the wrong side of review
Review/sign-off live in the incumbent audit file (the archived, inspected record); OTTO
builds its own notes/sign-offs/lock upstream of a one-way export. Review rounds force
fix→re-export→replace loops; under deadline seniors will edit the exported Excel directly,
the filed workpaper silently diverges, provenance doesn't travel, and OTTO's trail is
outside the record that counts. Which sign-off is authoritative is never decided.
**Demanded**: export/review boundary as a first-class contract; self-contained exports;
re-export flow; decide whether OTTO content is audit documentation.
**Response: ADOPTED** (within D3, which stands as founder default). ADR-013: OTTO
sign-offs = preparation + detailed-review record; the incumbent file's final sign-off
remains authoritative in v1; export is a terminal, versioned, hash-stamped event; the
exported workpaper is self-contained for inspection (embedded sample params, per-item
evidence refs + sha256s, modification history, review trail, version id); re-export
supersedes with an explicit supersession note; pilot kill-metric = review round-trips.
OPEN_QUESTIONS Q11 (OTTO content = audit documentation, default YES, retention per pack).

### CPO — the two-cycle MVP proves architecture, not a purchasable pain
The dual wedge serves two buyers, one of whom (network component auditors) structurally
cannot procure a startup sidecar; the cabinet buyer needs cycle (a) only. Half the MVP
surface adds nothing to the closable buyer's time-to-first-value; the load-bearing adoption
mechanism (live email intake) is stubbed; A5/A6/A7 stay untouched by the build.
**Demanded**: re-scope to NEP-only; SOX as schema + integration test; live email in MVP.
**Response: LOGGED (D2 stands — founder default explicitly mandates the two-cycle proof)
+ PARTIAL adoptions**: the SOX cycle remains but its UI scope is held to the minimum that
proves the loop (no RCM authoring UI — import/edit only); email intake keeps a real
interface with transport stubbed (running live SMTP is a deployment property, not
build-provable in this repo); A5/A6/A7 falsifiers re-stated as dated pre-pilot milestones
(ASSUMPTIONS). The buyer-intersection question is the founder's #1 review item.

### CTO — the acceptance gate is a closed loop that never touches extraction risk
Demo data is generated by the repo that must detect its own seeded anomalies; OCR/LLM rungs
are mocked; the deterministic rungs are exactly what the generator emits in perfect form.
OE evidence (screenshots, system reports, approval emails) has **no** deterministic rung at
all — the SOX cycle's extraction is rungs 3–5 or nothing, and it is mocked. No target
precision/recall, no verify-time budget; A9's falsifier deferred to post-v1.
**Demanded**: real-document eval corpus before build freeze; live rungs 3–5 as a gate;
explicit OE-extraction assumption; L2 economics threshold.
**Response: PARTIAL.** Cannot be fully executed inside this repo: real client-like
documents violate the synthetic-only rule, and this run has no basis to fabricate "real
messiness" honestly. ADOPTED: A11 (L2 verify-time economics) and A12 (OE evidence has no
deterministic rung; live extraction eval on a real permissioned corpus is a **pre-pilot
gate**, dated milestone, not post-v1); PRD acceptance criteria reworded — the offline suite
is a build-time regression, explicitly NOT extraction-reliability evidence; demo attribute
testing marks which attributes are extraction-derived vs human-assessed. The eval-corpus
milestone is the founder's #2 review item (requires permissioned real documents only the
founder can source).

### AI architect — L2 is undefined and the docs contradict each other on it
Assessment #7 says human-verify below confidence threshold; D5 says everything AI-generated
is L2-gated. Each resolution kills a different pillar (hours claim vs safety claim).
Confidence calibration is unbenchmarked and the auditee is a motivated adversary; the
missing register entry is "L2 verification of an AI-extracted item costs materially less
than manual performance".
**Demanded**: precise per-rung L2 ADR; injection boundary statement; A11-type assumption;
timed review benchmark + calibration benchmark on non-self-generated corpus, gating pilot.
**Response: ADOPTED.** ADR-012 resolves the contradiction explicitly: rungs 1–2
deterministic (L0/L1, spot-check control); rungs 3–4 always item-verified in v1
(side-by-side UI), confidence = triage ordering only, never a bypass; untrusted document
content never reaches a drafting prompt except through deterministic-match outputs (the
injection boundary, 06 §6.1 extended). A11 added. Benchmarks = pre-pilot milestones (same
constraint as above).

### Investor — two disjoint segments stapled together; the demo impresses the empty intersection
Network component auditors can't procure a solo-founder sidecar (mandated global platforms,
procurement, independence vetting); independent cabinets don't need SOX and their fee base
(~€4,220 median) caps per-mandate pricing at sub-scale ARR. A8 is mislabeled "not
build-relevant"; it decides whether the PCAOB pack belongs in v1. DataSnipper and
Fieldguide each picked one buyer and one motion.
**Demanded**: name ≥10 real independent European component-auditor firms + one group-auditor
acceptance confirmation, or delete the SOX cycle; reclassify A8 as kill-criterion.
**Response: LOGGED (D2/D11 stand as founder defaults; the demanded market verification
requires founder action, not build action) + ADOPTED**: A8 reclassified build-relevant
kill-criterion with a falsification test (≥15 WTP interviews; per-cabinet pricing floor;
named independent component-auditor list). Founder review item #1 (same as CPO).

## Red team — three strongest arguments

1. **The wedge proves a property, not a purchasable pain**; the two buyers form a
   near-empty intersection (network firms can't buy; cabinets don't need half the build).
   *Disposition*: LOGGED — founder's D2/D11; the strongest standing argument against the
   program. The build continues per contract; the GTM falsifiers are now dated
   kill-criteria (A8, A13).
2. **D3 (sidecar) + D5 (universal L2) + the wedge's true evidence mix jointly negate the
   headline ROI and moat claims**: provenance flattens at the export boundary; verification
   + double-maintenance hours are unmodeled; most revenue-cycle evidence (delivery notes,
   contracts, PODs, SME invoices pre-2027) sits below the XML rung.
   *Disposition*: PARTIAL — ADR-012/013 + self-contained exports address the boundary and
   the verification act; the Factur-X claim is corrected in 02 (helps invoices
   progressively, not the whole evidence mix); the honest-hours model is A11, pre-pilot.
   The residual argument (sidecar caps the moat) is real and stands logged against D3.
3. **The validation plan is self-referential** — the program can hit 100% of its acceptance
   criteria while learning nothing decisive (seeded-anomaly detection validates the
   generator; mocked adapters exempt the riskiest layer; every commercial assumption defers
   to a pilot that doesn't exist; secret-professionnel hurdle unanalyzed).
   *Disposition*: ADOPTED in wording (acceptance = build-time regression, never reliability
   evidence; A9 reworded), PARTIAL in substance (pre-pilot gates A11/A12/A13 are dated
   kill-criteria; professional-secrecy analysis added to 06 roadmap). Residual: true — v1
   is an engineering artifact; first contact with reality is the pilot. The contract
   (build 100% in this run) accepts that risk explicitly.

# GATE 2 — after Stage B (2026-08-25)

## Lens objections (condensed) and dispositions

### Audit partner — the substantive loop concludes without a sample-evaluation mechanic
No tolerable misstatement, no projection of random-stratum errors to the untested
population, wrong conclusion gate ("exceptions resolved?" — contradicted by the demo's own
uncorrected misstatement at step 10 vs sign-off at step 12), and `verification_check`
disagree had no consequence flow.
**Response: ADOPTED in full.** `materiality.te_pct/te_amount` + `sample_evaluation`
(known/projected misstatement, method, untested remainder, vs-TE comparison) added to the
schema (0001/0002 before first commit of the migrations); projection math is kernel
arithmetic (S3/S6 DoD, unit-tested); NEP/PCAOB workpaper formats gain a mandatory
evaluation section (`wp.evaluation`); conclusion gate re-specified: *all exceptions
dispositioned (resolved or promoted to misstatement) AND aggregate known+projected
misstatement evaluated against TE — human concludes (L4)*; verification disagree
auto-raises a `verification_disagreement` exception + documented expand-or-reperform
decision rendered in the spot-check section.

### Senior manager — one-pass pipeline vs how fieldwork actually runs
(a) Request items restricted to sampled units would block standing PBC; (b) re-import
supersession orphans sample/request/match provenance; (c) the seeded TB↔FEC mismatch
collides with an absolute reconciliation hard gate.
**Response: ADOPTED.** (a) 03 §1.1 corrected — the over-asking mitigation applies to
*evidence-per-tested-unit* items; procedure-level standing items (listings, TB/GL/FEC,
explanations) exist from day one (schema always allowed it). (b) `gl_entry.natural_key`
(journal|entry|line) + `gl_entry_supersession` carry-forward + **ADR-016 hard rule**:
TB/GL re-import after a drawn sample requires an explicit invalidation confirmation that
supersedes dependent samples (events logged); top-up draws (`supersedes_sample_id`,
`carried_from_item_id`) preserve tested items. (c) `reconciliation_item` rows carry
`open|documented_difference|resolved`; the population gate is **per tested FSLI's
accounts**, and a documented difference passes with the difference rendered in the
workpaper.

### CPO + CTO + skeptical engineer + red team (convergent) — the acceptance oracle freezes before the semantics that define it exist
C1 committed a dataset whose "zero false negatives" contract depends on importer
canonicalization (S1), materiality caps (S2), population/flags (S3), tolerances (S6) and
the draw itself; any later fix silently moves the draw off the seeded anomalies and
detonates a regeneration cascade (PDFs → sha256s → extraction fixtures → export
expectations) at the worst point of the run. The SOX attribute loop is maximally coupled
(12 instances, draw of 3). Demo's "adjust materiality" step can unsample the anomalies.
**Response: ADOPTED — build order restructured (ADR-015).** C1 splits:
- **C1a — deterministic kernel (before any dataset bytes)**: gl_entry canonicalization +
  natural-key spec, population_hash canonical serialization (versioned, single module),
  PCG→FSLI map, population builder + ADR-003 flags, materiality math, sampling engine
  (both methods), vouching tolerance checks, projection math — pure unit-tested libraries.
- **C1b — generator imports the kernel**: computes the real draw under **pinned demo
  params** (`dataset/demo-params.json`, which the demo script's "adjust" steps land on),
  places anomalies robustly (substantive anomalies pinned to deterministic strata —
  high-value above coverage cap or risk-flagged — wherever possible; SOX deviations placed
  inside the pinned draw), and emits each PDF **together with** its extraction fixture and
  an expected-exception manifest so all fixtures co-move on regeneration; ANOMALIES.md is
  generator-emitted.
- **Placement-invariant test from C1 onward**: recompute population → flags → draw with
  current engine + pack config and assert every manifest anomaly is detectable; drift
  fails at the slice that caused it. Zero-FN is testable at C1, not S6.
- S8 split into S8a (RCM/D&I/instances/listing import) and S8b (attribute testing/
  deficiencies/OE workpaper); S8 UI held to four surfaces + deficiency panel. The
  listing→control_instance importer is **owned by S8a**; the SOX request flow is two
  requests (population listing first; per-sampled-instance evidence after the draw) — demo
  script fixed.

### AI architect — ADR-012 not implementable in the schema as specified
No engine-run identity for deterministic runs; drafted artifacts lacked ai_run links; the
spot-check subsample had no stored seed/params/population-hash (the one draw an inspector
probes); agree/disagree forecloses blind re-performance; disagree was a dead end.
**Response: ADOPTED** (migration 0006, before S6 consumes it): `engine_run` table (engine,
version, pack id, config hash, params) referenced from sample, match batches,
reconciliation, workpaper, deficiency; `ai_run_id` linkage for drafted workpaper sections
(per-section in sections jsonb), deficiency narrative, evidence classification;
`verification_run` header (seed, params, machine-passed population hash, rate) parenting
`verification_check`; blind capture: verifier's independent values recorded before the
machine result is revealed, agreement computed, disagree auto-raises an exception with a
pack escalation note. 07 S7/S8 ACs updated.
